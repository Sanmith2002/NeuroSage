# Output schema, version 1.0

Machine-readable contract: [`output_schema_v1.json`](output_schema_v1.json) (JSON Schema, draft 2020-12). Input contract:
[`input_schema_v1.json`](input_schema_v1.json) and [`input_features_v1.md`](input_features_v1.md). The JSON schemas are the
integration boundary between this component and the rest of the system; they are generated by
`python -m copath.inference --write-contracts --from-bundle`. The v1 inference input contract reflects the raw pre-pipeline feature
union of the frozen final model bundle. It is intentionally not identical to the broader modelling-tier candidate feature
configuration. `python -m copath.inference --check-contracts --from-bundle` (read-only) compares the committed input contract with the
frozen bundle.

One record in, one result out. Nothing is persisted. Exactly three research proxy signals are returned, always in this order:
`pd_type`, `ad_like`, `vascular_risk`.

```json
{
  "schema_version": "1.0",
  "participant_id": "<as supplied; may be pseudonymous; null when not supplied>",
  "model_version": "pd-copathology-v1.0",
  "selected_models_sha256": "<SHA-256 of the frozen selected_models_v1.yaml>",
  "generated_at": "<ISO-8601 UTC, e.g. 2026-10-15T08:30:00Z>",
  "signals": {
    "pd_type":       { "probability": 0.0, "model": "rf", "calibration": "sigmoid", "target_definition": "pd_type_v1",
                       "cohort_in_training_scope": true, "shap_space": "...", "shap_explains": "...", "top_features": [] },
    "ad_like":       { "...": "model lr_enet, target_definition ad_like_v1" },
    "vascular_risk": { "...": "model rf, target_definition vascular_v1" }
  },
  "data_quality": { "...": "see below" },
  "disclaimer": "Research proxy signals for co-pathology estimation. Not a clinical diagnosis. ..."
}
```

## Fields

| Field | Meaning |
|---|---|
| `schema_version` | Version of this contract (`"1.0"`). |
| `participant_id` | The caller's identifier, echoed unchanged. Never a model feature. |
| `model_version` | Frozen bundle version, derived from the bundle (`pd-copathology-<final bundle version>`). |
| `selected_models_sha256` | SHA-256 of the frozen model selection this result was computed with. |
| `generated_at` | UTC time of the computation. |
| `signals.<name>.probability` | **Calibrated** probability (0 to 1) of the research proxy signal, from the frozen calibrator. |
| `.model`, `.calibration` | Estimator family (`rf`, `lr_enet`) and calibration method (`sigmoid`). |
| `.target_definition` | Identifier of the frozen label definition (`pd_type_v1`, `ad_like_v1`, `vascular_v1`). It says what the signal is a proxy for; it is not a diagnosis. |
| `.cohort_in_training_scope` | Whether the **supplied** `cohort` is within the cohort scope this signal was trained on (see below). `null` when no cohort was supplied. |
| `.shap_space` | The space the contributions live in (recorded in `explainer_specs.json`). |
| `.shap_explains` | Always states that the contributions explain the uncalibrated model output. |
| `.top_features` | Up to 5 **observed** input features with the largest absolute contribution (see below). |
| `data_quality.*` | Descriptive completeness of the supplied record, computed before any imputation (see below). |
| `disclaimer` | Fixed text. |

### What is deliberately not in the output

No binary class decision, no decision threshold, no diagnosis or treatment recommendation, no out-of-distribution flag and no
TRUST / CAUTION / DEFER. Reliability and those decisions belong to the downstream Clinical Predictive Safety Framework.

## Explanations (`top_features`)

Each entry is `{"feature", "modality", "shap", "direction"}`. `direction` is `"increases"` when the contribution is positive and
`"decreases"` when it is negative; features whose contribution is exactly 0 are left out. Raw participant values are not included
(data minimisation); this can be added later as an explicit integration decision.

**Frozen explanation convention** (packaged in `models/final/<version>/packaging/explainer_specs.json`; inference reads and obeys it
and has no fallback explainer):

| Signal | Convention |
|---|---|
| `pd_type` (RF), `vascular_risk` (RF) | `shap.TreeExplainer` on the frozen **uncalibrated** random forest, `feature_perturbation = tree_path_dependent`, no external background data. Output space: probability of class 1 of the uncalibrated model (class index as recorded in the spec). |
| `ad_like` (elastic-net logistic regression) | Linear contribution `contribution_j = coef_j * scaled_value_j` with base value = the fitted intercept, in the **uncalibrated log-odds (decision-function) space**. The reference is the zero vector in scaled space, which is the mean of the final model's own training representation. This matches the Phase 3 `LinearExplainer` convention (mean of the training background) without any development data at inference time. |

- The contributions **do not sum to the calibrated probability.** They explain the uncalibrated model score; the calibrated
  probability is what is presented as the prediction. `shap_explains` says so in every result.
- **Additivity guard (runtime):** for every record and signal, base value + the sum of the contributions over **all** estimator columns
  (before any filtering) must equal the uncalibrated model output in the recorded space within 1e-6. Otherwise the record fails with an
  error and no explanation is returned.
- Features dropped by the frozen pipeline as degenerate map back to their original names with contribution 0. If one raw feature
  were to produce several estimator columns, their contributions are summed per raw feature.
- **Correlated and redundant inputs.** Some inputs are highly correlated, redundant or near-duplicate representations (for example hy / NHY,
  age / age_at_visit, and related plasma p-tau217 assays). Tree and linear models may split attribution across correlated predictors, so
  more than one related feature may appear in top_features. This reflects the frozen model representation and should not be interpreted
  as independent causal importance.
- **Observed features only.** The frozen pipeline imputes a missing feature, so a missing feature can carry a non-zero internal
  contribution. It is **never** listed in `top_features`. "Observed" means: supplied with a non-null value that passed strict validation.
  Ranking is by absolute contribution, ties broken by feature name, so the output is deterministic. If no model feature was observed,
  `top_features` is `[]`.

Implementation verification note (not a schema rule): the frozen explanation conventions were verified locally against the
development data after final model locking. Maximum absolute numerical differences were below 2e-15 for all three selected models,
consistent with floating-point precision.

## `cohort_in_training_scope`

Whether the supplied `cohort` value lies within the cohort scope used to train **that signal** (it is not a statement about whether
the person was in the training data). `pd_type`: `PD` and `HC` are in scope, `Prodromal` and `SWEDD` are not. `ad_like` and
`vascular_risk`: all baseline-universe cohorts (`PD`, `HC`, `Prodromal`, `SWEDD`) are in scope. No cohort supplied: `null`. The cohort is
never inferred from the features and is never a model feature. Any other cohort string is an input validation error.

## `data_quality` (descriptive only, not a reliability judgement)

Computed on the supplied record **before any imputation**: `n_features_expected` (union of the raw features the three frozen
pipelines use), `n_features_observed`, `feature_completeness` (their ratio), `available_modalities`, `missing_modalities`,
`modality_completeness` (observed fraction per modality), `per_signal_completeness` (observed fraction of each signal's own
features) and `n_unrecognised_fields` (supplied fields the pipelines do not use; their names are not echoed).

## Strict input validation

A supplied field that cannot be parsed as its declared type (number) is an **input validation error** that names the field and
never shows the value; no prediction is produced. A malformed value is never silently turned into a missing value. An explicit
`null` or an empty cell counts as absent and becomes missing for the frozen pipeline, which alone decides how it is handled. There
is no lenient mode in version 1.

**Scope of input validation.** Input contract v1 validates presence/missingness and numeric type only. It does not currently validate
clinical plausibility, physiological ranges, or feature-specific categorical codes (for example, a binary numeric feature supplied
as 7). Out-of-range or implausible numeric inputs are still processed by the frozen models and may produce unreliable probabilities.
Clinical-range validation, categorical-code validation, and out-of-distribution assessment are outside the current inference contract
and must be handled by the caller, the downstream Clinical Predictive Safety Framework, or a future contract version with explicitly
documented ranges.

## Synthetic demo record

`python -m copath.inference --make-synthetic-example <file>` writes a record with `participant_id` `SYNTHETIC_DEMO_001`. The synthetic
demo record uses deterministic values derived from feature names solely to exercise the inference pipeline. Many values may be outside
realistic clinical ranges. Its probabilities and feature contributions have no clinical or scientific interpretation and are for
engineering smoke testing only.

## Integrity

Before any prediction the frozen bundle is verified with the same code as `python -m copath.phase3 package-final-bundle --verify`
(file hashes, ordered feature-list hash, selection hash, explainer specification, exact scikit-learn version). Any failure stops the
run; there is no fallback to an unverified bundle.
